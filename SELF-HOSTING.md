# Self-hosting priority

Canvas should prove itself against the smallest real environment that contains its own implementation before it is used to visualize a larger external system.

The first source witness is **Canvas projecting the Canvas repository itself**. The first real Board then composes that source using the generic Board grammar.

## Order of evidence

1. **Canvas -> repository field** — project the exact Canvas Git revision into portable grounded Objects + real `contains` Connections.
2. **Repository field -> first Board** — add the explicit premise `What exists here, and how is it contained?`; render those same Objects as Cards; render those same `contains` Connections as visible relations; arrange them hierarchically inside a generic Frame.
3. **Other Git repositories -> Canvas** — use the same projector and Board composition machinery unchanged against larger repositories as scale/conformance witnesses.
4. **Additional providers / Board premises** — widen only when a source or question cannot be faithfully expressed by the existing grammar.

The first Board is directory-like because of its premise and relation topology. `directory` is not a Canvas primitive or special Board class.

A larger repository such as Soveraeign is useful as a later scale witness, but it is not the first product demonstration and must not define the Canvas object model.

## Self-hosting acceptance

For an exact Canvas commit, CI must:

- enumerate the complete tracked Git tree at that commit;
- project every real tree/blob as an ordinary grounded `reference` Object;
- project only Git parent/child membership as `contains` Connections;
- author a premise-bearing Board without duplicating those Objects or Connections;
- place all represented Objects inside one generic Board Frame;
- render each represented Object through the ordinary Card boundary;
- render every Board relation from stored `contains` Connection records;
- validate the generated Board document against the portable 0.1 contract;
- resolve every GroundRef to its exact Git object;
- preserve exact-byte text/HTML Card rendering;
- regenerate both repository field and Board byte-for-byte from the same revision;
- publish the `canvas-first-board` artifact.

The Board is an authored composition over the repository field. It is not a second repository and has no authority over Git.
